# TENGIZ — бекенд (API)

Сервер на **Node.js + Express**, база **SQLite** через **Prisma**.
Одна БД — спільна для сайту й (згодом) Telegram-бота.

## Запуск (перший раз)

```bash
cd server
npm install
npx prisma migrate dev   # створює БД і застосовує схему
npm run seed             # наповнює демо-даними
npm run dev              # старт із авто-перезапуском → http://localhost:4000
```

Далі щодня достатньо `npm run dev`.

## Корисні команди

| Команда | Що робить |
|---|---|
| `npm run dev` | Сервер з авто-перезапуском при змінах |
| `npm start` | Сервер без перезапуску (прод-режим) |
| `npm run seed` | Перезаповнити БД демо-даними |
| `npm run db:reset` | Стерти БД і накотити міграції + seed заново |
| `npm run db:studio` | Візуальний перегляд БД у браузері (Prisma Studio) |


## Telegram-бот

Бот вмикається **лише** якщо в `.env` є `TELEGRAM_BOT_TOKEN`. Без токена сервер і сайт працюють як зазвичай.

Підключення:
1. Візьміть токен наявного бота у **@BotFather** (`/mybots` → бот → *API Token*).
2. Впишіть його в `server/.env`: `TELEGRAM_BOT_TOKEN="..."`.
3. (Опційно) перевірте стан бота — безпечно, лише читання:
   ```bash
   npm run bot:check
   ```
   Покаже, чи токен робочий і чи не «зайнятий» бот іншим кодом (вебхуком).
4. Виставте назву, описи й меню команд бота:
   ```bash
   npm run bot:setup          # застосувати
   npm run bot:setup -- --dry # лише показати різницю
   ```
   Усі ці тексти лежать у `scripts/setup-bot.js` (об'єкт `SETTINGS`) — правити треба там, а не в BotFather.
5. Запустіть сервер (`npm run dev`) — у логах з'явиться `🤖 Telegram-бот @... запущено`.
6. Лікар відкриває бота й надсилає **`/bind ваш_пароль`** (пароль власника) — цей чат стає отримувачем записів.
   Після цього варто повторити `npm run bot:setup`: команди лікаря (`/add`, `/slots`) додаються в меню **лише його чату** — пацієнти їх не бачать.

### Заміна бота (тестовий → робочий)

Розробка йде на власному тестовому боті, потім переходимо на бота клініки. Код при цьому не змінюється:

1. `TELEGRAM_BOT_TOKEN` у продакшн-оточенні = токен робочого бота, рестарт сервера;
2. `npm run bot:setup` — та сама косметика застосовується до нового бота;
3. власник тисне **Start** і надсилає `/bind ваш_пароль` (без Start бот не має права написати першим — Telegram відповість `403`);
4. `npm run bot:setup` ще раз — щоб з'явилось меню команд лікаря.

Один токен = один запущений екземпляр: не тримайте локальний сервер із продакшн-токеном одночасно з продом, інакше Telegram віддає `409 Conflict`.

### Що приходить лікарю

- **новий запис із сайту** — з кнопками **✅ Підтвердити / ❌ Скасувати**: вони міняють статус у
  спільній БД (видно на сайті й в адмінці) і одразу пишуть пацієнту; під повідомленням бот
  дописує, чи сповіщення дійшло («🔕 Пацієнт не відкривав бота — варто подзвонити»);
- **скасування пацієнтом із кабінету** — окремим повідомленням: «час знову вільний на сайті»;
- **повідомлення пацієнтів** — копією, з відповіддю реплаєм;
- **збій нагадування** (пацієнт заблокував бота) — попередження «варто подзвонити».

Команди лікаря в боті:
- **`/add`** — додати вільні години (обрати послугу → надіслати `ДД.ММ ГГ:ХХ`, можна кілька рядків);
- **`/slots`** — переглянути вільні слоти й видалити зайві (кнопка 🗑).

Слоти з бота й із сайту — це одні дані (спільна БД), тож усе синхронно автоматично.

### Що отримує пацієнт

Telegram не дозволяє написати людині першим — потрібен її `chatId`. Тому на екрані «Готово»
після запису сайт показує кнопку з посиланням `t.me/<бот>?start=r_<id запису>`. Щойно пацієнт
тисне **Start**, бот запам'ятовує його чат у профілі (`User.telegramChatId`) — і далі сам пише:

| Коли | Що надсилає |
|---|---|
| Лікар натиснув ✅ / ❌ (бот або адмінка) | «Запис підтверджено» / «Запис скасовано» з послугою, часом і адресою |
| За добу до візиту | нагадування з днем тижня й часом |
| За годину до візиту | коротке нагадування |
| Лікар відповів реплаєм | текст (або вкладення) лікаря |

⚠️ Під час тестування: payload `?start=r_<id>` Telegram передає боту лише разом із кнопкою
**START**, а вона з'являється тільки в чаті, який ще жодного разу не запускали. Якщо чат уже
активний (напр. чат лікаря), посилання просто відкриє діалог — щоб перевірити цей шлях,
надішліть команду `/start r_<id запису>` повідомленням.

Деталі нагадувань:
- перевірка щохвилини; рівні описані в `REMIND_TIERS` угорі `src/bot.js`
  (`beforeMin` — за скільки нагадуємо, `minLeadMin` — нижня межа: запис, зроблений за три
  години до прийому, нагадування «за добу» вже не отримає; `minAgeMin` — не пишемо одразу
  після запису, бо людина щойно сама обрала цей час);
- надіслане фіксуємо в `Booking.remindedDayAt` / `Booking.reminderSentAt`, тож рестарт сервера
  не спричинить дубль;
- скасовані записи не нагадуються; якщо пацієнт заблокував бота — лікар отримує попередження;
- пацієнт, який уже тиснув Start, отримуватиме сповіщення й про наступні записи автоматично.

Telegram не повідомляє, чи людина прочитала повідомлення, тож «повторити, якщо не прочитано»
технічно неможливо — замість цього маємо два нагадування в різний час.

### Мова пацієнта

Сайт двомовний, тож мову, обрану під час запису, зберігаємо в `User.lang` — і бот пише людині
саме нею (`src/botText.js`, ключі `uk`/`en`). Пацієнт може перемкнути мову в боті командою
**`/lang`**. Лікар бачить усе українською; якщо пацієнт спілкується англійською, у повідомленні
про новий запис з'являється позначка 🇬🇧.

### Часовий пояс

Усі години рахуються за поясом клініки — `CLINIC_TZ` у `.env` (типово `Europe/Kyiv`).
`src/time.js` виставляє його для всього процесу, тому `25.08 10:00`, додане в боті,
означає 10:00 у Києві, навіть якщо сервер хостингу живе за UTC. Там же — усі формати дат.

## Підтвердження запису через бота

Передоплати немає. Натомість запис із сайту **обов'язково підтверджує сам пацієнт у Telegram**,
і лише потім він потрапляє до лікаря (`src/holds.js`):

```
запис на сайті → pending_client (слот зайнято, holdUntil = +BOOKING_CONFIRM_MIN хв, типово 30)
   │  сайт показує кнопку/QR «Підтвердити в Telegram» (t.me/<бот>?start=r_<id>)
   ├─ пацієнт ✅ у боті → pending   → лікарю «🆕 Новий запис» з кнопками ✅/❌
   │     ├─ лікар ✅     → confirmed → пацієнту «🎉 Ви успішно записані», далі нагадування
   │     └─ лікар ❌     → canceled  → пацієнту «запис скасовано»
   ├─ пацієнт ❌ у боті → canceled  → слот одразу вільний (лікар нічого не отримує)
   └─ час вийшов        → canceled  → прибиральник щохвилини звільняє слот, пацієнту пояснення
```

Якщо пацієнт уже колись відкривав бота (його `telegramChatId` відомий), прохання підтвердити
приходить у бот одразу — переходити за посиланням не обов'язково.

Записи, які лікар вносить сам в адмінці (дзвінок, Telegram), цей крок пропускають.
Без `TELEGRAM_BOT_TOKEN` підтверджувати нікуди — тоді запис одразу стає `pending`.

## Бот для пацієнта: запис, відгуки, питання після прийому

- **Запис у боті** (`/book`, кнопка «🗓 Записатися»): послуга → день → час → номер телефону
  (кнопкою «Поділитися номером», лише свій — один раз; профіль шукається за телефоном, як на сайті)
  → «✅ Записатися». Запис одразу `pending` (`source: "telegram"`) і йде лікарю з ✅/❌.
  Слоти ті самі, що на сайті (`slotsLib.bookSlot` атомарно займає слот). Ліміт — 3 активні записи.
- **Мої записи** (`/my`) — майбутні записи з кнопкою скасування; лікар отримує сповіщення.
- **Питання від лікаря** через `FOLLOWUP_DAYS` днів (типово 7) після прийому (`confirmed`/`completed`),
  лише з 10:00 до 20:00. Відповідь пацієнта приходить лікарю з підписом «відповідає на ваше питання»,
  лікар відповідає реплаєм — діалог іде через TelegramRelay. Під питанням — «⭐ Оцінити прийом».
- **Відгук у боті** (`/review`) — зірки + текст → одразу на сайті (`Review.source = "telegram"`).
  Право на відгук (і на сайті, і в боті): прийом `completed` або `confirmed`, що вже минув.
- **Лікарю** приходить кожен новий відгук (із сайту й із бота) з кнопкою «🗑 Прибрати з сайту»;
  якщо автор на зв'язку в боті — подякувати можна реплаєм.

## Google Calendar лікаря

Кожен запис (із сайту, бота чи адмінки) сам з'являється в Google Calendar лікаря й живе там разом зі статусом:

| Що з записом | Що в календарі |
|---|---|
| пацієнт підтвердив у боті / записався в боті / додано в адмінці | подія `⏳ Ім'я — Послуга` (жовта) |
| лікар підтвердив | та сама подія без ⏳ (зелена) |
| відбувся / не прийшов | `✔` сіра / `✖` червона |
| скасовано (будь-ким) | подію видалено |

В описі події — телефон, Telegram, ціна, статус і звідки запис. Поки пацієнт ще не підтвердив запис
із сайту в боті (`pending_client`), у календар нічого не йде. Старі записи при першому вмиканні не
заливаються — лише від учорашнього дня.

Код — `src/gcal.js`: раз на 30 с він бере записи, змінені після останньої звірки
(`Booking.updatedAt > gcalSyncedAt`), і приводить подію у відповідність. Тож не важливо, де змінили
запис, а якщо Google недоступний — наступний прохід доробить. Якщо лікар видалив подію в календарі
вручну, назад вона не повертається.

### Підключення (один раз, ~10 хвилин)

1. [console.cloud.google.com](https://console.cloud.google.com) → створити проєкт (напр. `tengiz`).
2. **APIs & Services → Library** → *Google Calendar API* → **Enable**.
3. **IAM & Admin → Service Accounts → Create service account** (назва будь-яка, ролі не потрібні).
   Відкрити його → **Keys → Add key → Create new key → JSON** — скачається файл-ключ.
   Скопіюйте email акаунта (`…@….iam.gserviceaccount.com`).
4. **Лікар** у Google Calendar (з комп'ютера): ⚙️ біля свого календаря → **Налаштування та спільний доступ →
   Надати доступ певним людям → Додати** → email сервісного акаунта з кроку 3 →
   дозвіл **«Вносити зміни в події»**.
5. Змінні оточення (локально — `server/.env`, на Railway — Variables):
   ```
   GOOGLE_SERVICE_ACCOUNT='{"type":"service_account", … весь вміст JSON-файлу …}'
   GOOGLE_CALENDAR_ID=likar@gmail.com
   ```
   `GOOGLE_CALENDAR_ID` — gmail лікаря (так звуться основні календарі) або id окремого календаря
   (*Налаштування календаря → Інтеграція календаря*). Ключ можна дати й у base64.
6. Перезапуск — у логах: `📅 Google Calendar: записи синхронізуються в …`.
   Помилка доступу видно там же (`📅 Google Calendar 403/404 …` — найчастіше не зроблено крок 4).

Без цих змінних синхронізація просто вимкнена. Файл-ключ — секрет: у git не кладемо.

Якщо старий бот теж пише в цей календар — після переходу на новий вимкніть у старому інтеграцію, інакше записи задвояться.
